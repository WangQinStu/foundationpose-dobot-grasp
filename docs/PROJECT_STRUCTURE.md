# Project Structure

This workspace is organized as a top-level integration project with three preserved subprojects.

## FoundationPose

`FoundationPose/` contains the real-time vision side:

- `run_realsense_yolo_foundationpose.py`: main entry point for the integrated RealSense + YOLO + FoundationPose loop.
- `yolo_foundationpose/`: project-specific runtime package, including config, RealSense capture, masks, Dobot UDP publishing, and visualization.
- `yolo26/`: YOLO target selection helpers plus current local mesh/weight assets used by the demo.
- `debug/`, `demo_data/`, `weights/`, `downloads/`: local/generated data. These are ignored by the root `.gitignore`.

## SDFR

`SDFR/` contains optional refinement code and related tools:

- `sdfr.py`, `run_sdfr.py`, `run_sdfr_simreal.py`: SDFR refinement entry points.
- `lib/`, `utility/`, `my_tools/`: supporting code and data preparation utilities.
- `_results/`, `results/`, `temp_datasets/`, generated render datasets: local/generated data. These are ignored by the root `.gitignore`.

## Dobot ROS 2 Workspace

`dobot/` is a ROS 2 workspace:

- `src/dobot_pick_place/`: project-specific pick/place package.
- `src/DOBOT_6Axis_ROS2_V4/`: Dobot vendor ROS 2 packages.
- `src/Step_Motor_ROS2/`: step motor/gripper packages.
- `build/`, `install/`, `log/`: generated by `colcon`; ignored by the root `.gitignore`.

## Why The Top-Level Layout Is Preserved

The current working setup depends on relative paths and ROS 2 workspace conventions. Keeping the three main directories in place avoids changing runtime behavior while still making the repository easier to understand and upload.
